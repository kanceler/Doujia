## Findings

- 2026-05-08: JSON return contracts must be explicit even in synthetic scheduler fixtures.
- 2026-05-08: Synthetic scheduler tests should create real DoujiaGit bag facts for any preloaded instance input bag. Plain bag ID strings are rejected when snapshot facts consume them.
- 2026-05-08: For current runtime semantics, aggregate fixtures that join concrete bag arrivals should prefer `proof.mode="join_bags"` over state-id-only `mode="all"` unless state-to-bag mapping is explicitly implemented.
- 2026-05-08: The first scheduler gap found by complex JSON testing was aggregate re-entry after branch completion. The fix is intentionally narrow: after a non-aggregate pipeline transition updates instance bags, the orchestrator re-checks ready aggregate states for that same instance.
- 2026-05-08: Call-return fixtures must declare child signature agents in the child namespace, not only in the parent namespace.
- 2026-05-08: Current call-return scheduling can be tested without agents by starting parent/child pipeline instances and feeding synthetic child output bags through `OnFeedback`.
- 2026-05-08: Recover/repair JSON fixtures must explicitly bind input bags for called pipelines; inherited parent state is not guessed by the validator.
- 2026-05-08: The current repair path records immutable failed snapshots and repair branch metadata, including failed snapshot ID, failure report bags, previous output bags, and repair target task/transition.
- 2026-05-08: Partial repair must preserve non-replaced failed input bags as reusable sibling context. The retry task should receive repaired bags plus reusable sibling bags, and the repair snapshot should record producer snapshots for those reusable siblings.
- 2026-05-08: The new full-delivery entry combines a legacy task prefix with JSON call graph continuation. When the legacy prefix reaches its final JSON transition, the orchestrator must resume the root pipeline instance instead of treating the run as complete.
- 2026-05-08: Object input bindings such as `{"name":"front_module_input"}` refer to the parent-side bag name; they should not be overwritten by the child-side input alias like `module_input`.
- 2026-05-08: `mode="foreach"` needs to preserve indexed collection metadata while remapping parent bag names to child input aliases; backend module fanout uses `module_key` from the source bag indexes.
- 2026-05-08: Aggregate `proof.states` cannot rely on a fixed `state -> bag name` table for complex JSON flows. The scheduler needs to resolve referenced states through those states' declared `exposes`, especially for full-delivery stages like `front_module_done`, `backend_group_done`, and `global_test_data_done`.
- 2026-05-08: When a later aggregate references a specific prior state's exposed bag, it should prefer that state's output projection before falling back to current input bag lists. Otherwise previously aggregated inputs can leak back into new call bindings and duplicate bags such as `global_test_input`.
- 2026-05-08: After `merge_code` returns from its child pipeline, the root pipeline can continue on the JSON happy path without additional legacy glue: `code_merged` dispatches `pipeline_global_test_code`, and a successful child return completes the run into `awaiting_acceptance`.
- 2026-05-08: Local recover loops such as `global_test_code -> debug_global_code -> global_test_code` need replacement semantics even when the JSON omits explicit `replace_bags`. Using the recover state's exposed bags as the implicit replacement set keeps retries from carrying both old and new `merged_code`.
- 2026-05-08: Exported output handlers on completed child pipelines are still useful after delivery. If a later repair dispatch reuses that child pipeline, a second completion must not be treated as a no-op; the refreshed child outputs still need to propagate back into the already-completed parent/root instance.
